# UI & Design Preferences

- Treats visual polish as an explicit deliverable, not an afterthought — asks for the interface to be made better/"nicer" alongside the functional work (e.g. "rubah tampilan UI agar lebih oke lagi"). Confidence: 0.6
- When improving the UI, is open to a full redesign (design tokens, shared component primitives) rather than only incremental tidy-ups, and wants theming support such as a light/dark toggle. Confidence: 0.5
- Wants empty/no-result states to explain *why* nothing matched (e.g. which filter/gate rejected what, or near-miss items) instead of showing a bare, silent empty list that reads as broken. Confidence: 0.5
- Wants distinct functional areas separated by a tabbed menu bar / navigation rather than crammed into one long scrolling page — explicitly referencing the multi-panel layout of broker dashboards as the model. Confidence: 0.6
